# 服务节点连接与局域网发现

## 使用

电脑启用局域网访问后，在「拾文 → 手机配对与访问设备」生成配对码。手机进入「设置 → 服务与同步」，选择「扫码连接服务」，也可在节点设置粘贴配对码。旧节点选择「扫码升级连接」保留 nodeId 和资料库绑定。配对码两分钟有效、只能使用一次。

已配对节点支持多个 HTTPS 地址；当前地址正常时保持使用，失败时尝试备用地址和局域网发现地址。节点设置可手动添加备用地址。二维码和发现服务只包含已经监听成功的地址。关闭电脑的局域网访问时，不公告局域网入口。

手机在前台约每 30 秒检查连接，网络变化及返回前台立即检查。连续失败后显示离线，并退避到最长 120 秒。后台停止周期检查和发现；已有后台同步任务按原同步条件运行。页面显示在线、需要登录、手机无网络、检查中、离线、身份不匹配、服务响应异常，连接状态与资料库完整性分开。

## 信任与认证

- 服务使用持久 ECDSA P-256 密钥，存于服务目录的 `service-identity.pem`，权限 0600；普通资料库备份不包含它。
- 第一次信任来自电脑上的二维码。发现公告的名称和指纹只是定位提示，不能建立信任。
- Android 在 TLS 握手中验证配对公钥，再发送设备授权和业务内容；不跟随重定向，不全局放宽 TLS 验证。证书续期不更换服务密钥。
- 设备授权复用现有访问会话表。撤销设备或修改访问密码会使授权失效；访问密码修改也撤销未使用的配对码。
- 原 HTTP 节点保持兼容，仅使用手工配置的原地址；升级配对前不自动尝试发现地址。旧 HTTP 无法可靠识别 IP 被其他电脑占用，设置页会提示升级。

## 入口与同步

新增 HTTPS 端口默认为原服务端口加一（3080 对应 3081）。每个实际地址单独监听；新地址监听成功后才发布 `_shiwen._tcp`。普通虚拟网卡不自动选取，明确选中的本机网卡可使用。每十秒刷新网卡，移除的入口停止接收新连接，现有请求最多排空三十秒。端口冲突的地址不会公告或出现在配对码中。

电脑窗口使用独立的回环入口，和 LAN 入口复用同一 DSH 路由、认证和资料库。LAN 变化不会重启数据库，也不把桌面窗口绑定在某个 LAN IP 上。HTTPS 入口只接收固定原生 RPC 路径和配对、登录、状态请求。

每个节点的候选快照有限（最多 16 个）；当前地址优先，其余地址轮换，避免失败地址长期阻塞新候选。每次探测有超时，每轮有时间预算。配置绑定版本与连接代次分开：已核验的地址切换不清除登录、人设、游标、待上传内容或附件进度。迟到的旧代次探测不能覆盖新状态。

同步读请求遇到传输中断时最多重新选址重试一次。写请求从不自动重发；原操作编号、未知结果和服务端回执逻辑保留，下次同步先查回执。库身份与 epoch 仍由同步协议核验，服务身份一致不等于资料库可以替换。

## 验证范围

自动化覆盖持久密钥、证书公钥、一用配对码、真实 TLS 请求、错误公钥不发送授权、重定向不转发授权、设备撤销、多地址监听增减、候选轮换和离线状态区分。本机真实 LAN 的 mDNS 公告与发现回环核验了指纹、就绪端口和网卡地址过滤。隔离真实 DSH 服务覆盖回环 HTTP / WebSocket、旧 HTTP、人设与同步 TLS RPC、共用认证和凭据日志排除。

Android 最低 API 28，目标 API 36。NSD 使用系统网络服务及前台 multicast lock；二维码扫描由原生相机权限流程授权。没有接入真实手机时，自动测试不替代真机扫码、局域网组播、VPN、多网卡、Wi-Fi 切换与覆盖升级验收。
