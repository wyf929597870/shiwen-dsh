# Android UI 巡检后统一修复方案

日期：2026-11-07。修订：评审后第二版。状态：待实施。本文件只规定修复范围、步骤和验收，不代表已经完成。

依据：本轮真机巡检报告（15 组流程、56 张截图、17 项问题）、`mobile-redesign-spec.md`、`mobile-redesign-execution-plan.md` 及已选“专注工作台”方案。本方案补充原实施计划；本轮问题的修复与验收以本文清单为准。

## 1. 交付目标与范围

完成后，手机上应有一致的标题、边距、表单和弹窗；列表让位于阅读，编辑首屏直接写正文；系统返回和页面返回行为相同；关联素材可正常选择；所有现有功能仍有明确入口。

本轮集中解决呈现与交互，并修复已发现的关联素材读取错误。不重写 Agent、同步协议、资料存储或草稿机制，不引入新 UI 框架、路由框架、全局状态库，不迁移用户资料，不以隐藏功能代替修复。

本轮不新增文章状态筛选。创作列表只移除无效的素材类型筛选；文章编辑中的状态选择继续保留。关联素材所需的本地查询条件扩展属于已发现错误的修复，不延伸为通用查询系统。

保留现有 requestId、revision、libraryId、草稿持久化、提交待确认、凭据保护等有实际作用的机制。减少重复提示、重复状态、空 catch 和样式覆盖；不能将“做减法”等同于删除数据保护。

## 3. 先固定六条界面规则

1. **一个标题**：根页面由顶栏显示栏目名；子页由同一位置显示返回、页面名、必要动作。删除重复的大标题和同名卡片标题。
2. **单层边距**：普通手机页面左右 16 CSS px，窄屏可降至 12；列表标题与日期共用左边线，设置行与正文不再逐层套卡片缩进。最终以实际逻辑视口和字体缩放验收，不拿截图物理像素当 dp。
3. **完整字段**：标签在上、输入区独占一行，宽度 100%、`min-width:0`；错误紧跟字段；动作单独一行。长标签换行，不能压缩按钮或靠缩小字体解决。
4. **少量语义颜色**：页面、内容面、输入面、正文、次要文字、边框、强调、警告、错误各有深浅主题变量。复选框和焦点使用同一强调色；禁用与只读有区别。
5. **触控与键盘**：交互目标按 48dp 等效尺寸设计；编辑和对话的主要操作在键盘出现时仍可达。安全区只补偿一次，不同时在 Web 和 Android 重复加底部空白。
6. **简单控件用原生能力**：短枚举继续用标准选择控件；资料库、会话等需要副标题和长列表的选项用现有底部面板方式。复杂选择才抽取公共面板，不把每个 select 都重做成自定义组件。

样式落在现有 `theme.css`、`style.css`、`shell.css`、`record.css`、`chat-redesign.css`、`settings-redesign.css` 中：明确变量、基础控件、外壳、模块各自职责，将同一选择器的重复声明合并，删除被替代的规则。不新增又一份“fix/override”样式文件，不靠不断增加选择器权重或 `!important` 修补。

## 4. 具体实施包

### A. 外壳、系统返回与页面状态（F04、F08、F09）

主要文件：`android/web/main.jsx`、`SettingsPanel.jsx`、`RecordPanel.jsx`、`android/bridge/library.mjs` 与类型声明、原生 `MainActivity.java` / `LibraryProbePlugin.kt`。

步骤：

1. 将页面描述（标题、是否子页、返回动作）与编辑状态（dirty、busy、提交待确认）分开，不能在同一个对象中相互覆盖。记录选择、编辑草稿和设置子页仍归所属组件管理；外壳不复制这些数据。
2. 每个活动页面只有一个编辑状态上报者：有子表单时父页面只转发，不再在父页面异步操作的 finally 中写入 `{dirty:false,busy:false}`。确有父级操作时，在同一归属处合并实际 busy 状态。使用活动页面实例的注册身份校验上报和注销，旧实例的异步完成或卸载不能清除新实例状态；新页面明确报告初始状态。这是局部所有权约束，不建立第二套页面状态仓库。`RecordPanel` 的列表／阅读／编辑与设置各层级向外壳报告页面描述，顶栏和底栏从同一描述推导。
3. 系统返回和可见返回按钮调用同一条处理路径：系统先收键盘／原生窗口；Web 弹层打开时先关闭弹层；随后编辑返回阅读、阅读返回列表、设置详情返回所属页，根页才执行 Android 默认离开行为。
4. 离开规则按下方行为表执行，不把“返回”“取消编辑”“丢弃草稿”合并成一个清理动作。同一次离开只询问一次。正在写入或结果待确认时继续使用现有阻止离开规则并展示原因，不清空草稿或提交标记。
5. 返回采用应用级桥接，不能经过要求资料库 context 已存在的 `call()` 路径，也不携带 `libraryId/pageGeneration`。复用现有原生插件载体，单独暴露返回监听就绪／注销和交还默认返回的方法，避免再创建业务插件。原生只在 Web 处理器已注册且页面可用时拦截；启动失败、资料库初始化失败且无可处理子页、WebView 销毁或处理器未就绪时保留原生返回。原生窗口和键盘优先使用自身返回处理。
6. 保留列表查询、筛选、已加载页数及滚动位置；新子页从顶部开始，返回恢复对应资料库和栏目位置。设置内部返回不能绕过子表单的 dirty 检查。
7. 主页面顶栏保留紧凑库名入口；阅读／编辑不提供突兀的大资料库区，身份可用一行次要文字保留。资料库面板补上新建、连接、管理入口，接到现有功能，不增加第二套创建逻辑。

返回交接约定：Web 处理一次请求后，要么消费该请求（关闭面板、返回一层、取消离开或提示不能离开），要么明确交还 Android 默认返回，不能两边都执行。异步保存／确认处理期间合并重复返回，不叠加确认框或跳过多层；结束后释放处理标记。监听只注册一次，使用当前页面处理函数；生命周期结束时注销。不采用超时自动退出，不建立通用事件总线。原生默认返回的交还须绕过自身拦截，避免递归触发。

离开与草稿行为表（系统返回、顶栏返回与相应可见按钮共用）：

| 场景 | 离开行为 | 草稿／数据结果 |
| --- | --- | --- |
| 对话输入或直接记录返回 | 等待现有草稿队列完成，再离开；失败就地提示，不静默离开 | 保留文字与类型，下次进入恢复；不因返回创建正式记录 |
| 素材／文章编辑，无改动 | 返回阅读；新建空白记录返回列表 | 可以清理对应空编辑草稿，不删除已存记录 |
| 素材／文章编辑，有未保存修改 | 返回或“取消编辑”均确认一次：“放弃修改／继续编辑” | 放弃时等待既有草稿清理成功才离开；继续编辑或关闭确认框时原样保留。清理失败留在原页 |
| 人设、任务、服务器配置等未提交表单 | 确认放弃才返回上级，取消确认不切页 | 不自动提交，不为统一返回而新增持久化系统；原有已保存内容不变 |
| 写入正在执行或提交结果待确认 | 留在当前流程，使用已有等待／核对提示 | 不丢弃 requestId、待确认标记或编辑内容 |
| 从根页离开应用 | 完成既有聊天／直接记录草稿写入；有当前阻止离开条件时按原规则处理，否则交给 Android | 不手动杀进程，不把离开应用当成清库或清稿 |
| 系统意外回收进程后重开 | 沿用已有草稿恢复机制 | 已支持恢复的记录／对话继续恢复；不承诺尚无持久化能力的设置表单恢复 |

新增记录的“有改动”按相同类型的初始表单判断，不能把预设的 article 类型／默认状态本身误算成用户编辑。切库和切栏目也使用所属页面的同一离开动作，防止确认放弃后仅卸载组件，却遗留会再次恢复的旧编辑草稿。

验收：素材列表 → 阅读 → 编辑 → 返回 → 列表，以及设置 → 服务 → 人设／插件详情 → 返回均逐层正确；确认取消后内容、选中项和滚动不变；输入后立即返回能保存直接记录草稿；旧页面卸载不覆盖新页面 busy；启动／初始化失败能正常退出；连续返回不跳层、不重复确认；键盘及原生窗口先关闭。

### B. 表单、主题与原生弹窗（F01、F02、F05、F14）

主要文件：`LocalAgentProfilePanel.jsx`、`RemoteChatPanel.jsx`、`AgentSettingsPanel.jsx`、`SettingsPanel.jsx`、上述样式文件；原生 `MainActivity.java`、主题资源及各 `*Dialog`。

步骤：

1. 本机人设拆为“身份、性格与行为、关于用户、记忆”四个纵向区域，保留 IDENTITY/SOUL/USER 为辅助说明。删除包住唯一内容的默认折叠层，保存按钮放在对应表单底部。
2. 服务器新会话使用纵向“工作区 → 助手 → 创建”布局；创建前不写服务端数据，已有选择逻辑不变。
3. 统一普通输入、文本域、选择框、复选框、错误、只读和禁用样式；补齐存储、记忆类型、自动化、插件能力提示等漏网控件。样式不覆盖系统密码处理或 Markdown 正文排版。
4. 原生主题从现有外观偏好读取，确定唯一更新入口。本轮采用不主动重建 Activity、不刷新 WebView 的切换方式：网页变量和系统栏即时更新，新打开的原生窗口使用当前主题／语言上下文。应用内切换及前台跟随系统变化不能调用 recreate 或导致页面重新初始化；保持当前页面、表单、滚动和会话。原生窗口通过适当的主题上下文适配，不把 recreate 作为备用修复路径；系统意外回收则沿用现有恢复边界。不为外观切换另建通用表单持久化系统。
5. 分别处理并验收四条路径：系统栏颜色／图标；WebView 自身的 select、日期、时间窗口；JS alert/confirm；凭据安全窗口。它们不是同一个主题机制，不能用其中一个通过代替其他项。JS 确认使用应用语言的按钮文案，复用或扩展现有 Capacitor ChromeClient 的对应方法，保留文件选择、权限等既有行为；不直接替换成空白 WebChromeClient。打开中的业务／安全窗口不因主题变化被销毁；返回应用后新窗口采用最新设置。
6. 所有凭据类窗口共用小范围的原生外观／文字来源；保留 `FLAG_SECURE`、密码掩码和敏感信息不进入网页的边界。共享的是外观，不抽成一个容纳所有业务字段的通用表单引擎。

验收：中文／英文、深／浅色下字段不混排、标签不粘连；长助手名和插件名不会挤窄关闭按钮；上述四条原生／Web 路径分别留证。编辑人设或任务期间改变系统主题并返回，未提交文字不丢；应用内外观切换不重置当前库、页面或会话；键盘打开时原生表单仍可滚动到动作区。

### C. 素材关联与发布检查（F03、F06）

主要文件：`RecordPanel.jsx`、`android/bridge/library.d.ts`、原生 `LibraryProbePlugin.kt`、`LibraryRepository.kt`、`LibraryDatabase.kt` 中的 DAO 查询及对应测试。不改数据库表结构、仓库上限或共享发布检查接口。

步骤：

1. 将关联素材请求改为现有协议允许的分页大小（最多 100）。给现有 `recordList` 增加可选 `excludeKind` 条件，本轮用于 `excludeKind:'article'`；桥接类型、原生参数校验、仓库方法和 DAO 一起接通。参数缺省时旧调用行为不变，已有 kind/deleted 查询语义不变；不新增查询端点或数据库迁移。
2. 关联面板分开表示首次加载、成功有内容、成功为空、失败；失败显示就地重试，删除空 `catch`，不自动无限重试。
3. 在数据库 WHERE 中按当前库、query、未删除及非文章条件筛选，再使用既有排序和 LIMIT/OFFSET。`nextCursor` 按筛选后的结果集生成，前端不再通过翻过多页文章来找素材，也不全库拉取后过滤。搜索沿用 query；分页失败保留已选项和已加载列表，重试当前游标，不跳页、不重复追加；恰好整页时允许沿用现有协议最后一次空页确认结束。
4. 候选项只包括当前库未删除的非文章记录。切换库或搜索条件后清空旧游标和候选；过期响应不能覆盖新查询。只做这一处必要的请求有效性检查。
5. 编辑已有文章时，已关联但不在当前候选页的 ID 仍保留，可按 ID 读取标题；缺失或已删除来源明确标注，不能因没加载到就清空关联。退出未保存不写入关联变化。
6. 隐私项改成：未匹配时“未发现常见敏感信息格式”，匹配时“发现疑似敏感信息，请检查”；统一说明“仅检查常见格式，仍需作者人工复核”。不声称可以判定文章完全安全。

验收：少于／等于／超过 100 条素材；按原排序前几百条全是文章而后面有素材时，首次候选查询就能返回素材；已删除来源不作为候选；搜索加分页无重复漏页（固定数据集）；缺省 excludeKind 的原列表结果不变；已有关联不在第一页、查询失败重试均不丢失 sourceIds。隐私文案与状态一致。

### E. 插件、自动化和设置管理（F10—F13、F15、F17）

主要文件：`SettingsPanel.jsx`、`ManagementPanel.jsx`、`PluginDetailsPanel.jsx`、`ScheduleTimingFields.jsx`、`LibraryReplicaPanel.jsx`、`RecoveryPanel.jsx`、`LibraryTransferPanel.jsx`、`ShareInboxPanel.jsx`。

1. 设置首页使用分组行，减少每行完整圆角卡片；每项仍进入现有功能，不堆成一个长表单。
2. 插件列表与插件详情采用当前模块内的两个视图，复用 `PluginDetailsPanel`；返回恢复列表位置。关闭／返回按钮固定可点击宽度，名称允许换行。
3. 按具体缺失能力显示“此服务未提供插件市场／任务管理”等，就近影响相应入口；可用列表不被一个全局不可用提示否定。权限拒绝、能力缺失和网络失败保留区别。
4. 自动化先显示任务列表和新增入口，点击进入新增／编辑；保留已有历史、立即运行、暂停等能力。时间默认 `HH:mm`；已有包含秒或毫秒的任务必须显示精细时间选项并原样保留，未选择修改时间时不重写 schedule。Cron、RRULE 和时区继续保留。
5. 服务节点概览只放名称、地址、连接状态、最近同步与主要动作。指纹、ID、原始错误、请求编号、内部状态放“诊断详情”；null 不作普通文本展示，日期统一可读格式。
6. 外部接入先展示授权列表，新建凭据进入表单；“通过原生窗口创建”改为“创建凭据”，保留真正影响用户决定的权限说明。
7. 恢复页保持来源、目标和将执行的动作清楚；收紧嵌套卡片，危险动作与普通动作分组，确认中继续写明操作对象。不能为了精简隐藏覆盖／恢复的实际影响。
8. 导入与备份分成“导入 Markdown、导出备份、从备份恢复”三个清楚入口；后续步骤展示原库恢复／新库导入区别，复用既有处理。分享空态保持简洁；存储页使用同一字段与统计规则。

验收：列表点详情后当前视口立即出现详情；长名称不挤坏动作；部分服务能力缺失仍可使用其他功能；只改任务标题不损失原有秒／毫秒时间；诊断仍可找到，但不挤占普通页面。

## 6. 实施顺序与集中验收

### 阶段 0：固定基线与边界

- 记录工作区现有改动、安装版本和构建产物身份；不覆盖前面已经完成的工作。
- 将审计 F01—F17 登记为“待修复”，列出全部弹窗入口和可用样本。原报告只作证据，不改成“已通过”。
- 记录原始列表／返回／草稿行为，用下方固定场景建立隔离预览；所有预览能力只用于开发，不向正式入口注入假数据。

**隔离预览的具体交付（以下文件与命令均为待新增，并非当前已可运行）：**

1. `android/preview/main.jsx` 作为独立开发入口，加载现有 Web 应用入口与真实页面组件，不复制一套页面 JSX。新增 `android/scripts/build-preview.mjs`，使用现有 esbuild，在仅预览构建中将对 `android/bridge/library.mjs` 的引用精确替换为 `android/preview/library.mjs`。正式桥接文件不加运行时 mock 开关，正式构建脚本继续使用真实桥接。
2. 预览桥只实现页面要用到的 bootstrap、只读列表和必要的表单响应；在替身内提供可启动页面的原生环境标记，不能修改正式环境判断。未知方法明确报出缺少模拟实现，不能返回通用成功结果。模拟写入只改变内存场景，不访问 Android、本机服务、真实资料、模型或浏览器持久化存储；不实现另一套同步／后端系统。
3. `android/preview/fixtures.mjs` 保存最小场景：正常列表、空结果、请求失败、分页、长名称、同名会话、缺少某项能力和待确认状态。以入口参数选择固定场景，刷新恢复初始数据；不使用用户资料截图里的正文作夹具。场景只证明界面分支，不代替真实 SQL、保存、同步或返回测试。
4. 计划提供 `npm --prefix android run preview:build`，输出到独立 `android/preview-dist/`；使用本机静态服务即可查看，不能输出到 Capacitor 的正式 `android/dist/`，也不能改 `webDir` 或 `server.url`。不额外引入开发服务器框架。原生窗口用明确“仅原生可验证”的占位边界，不绘制假弹窗冒充实际结果。
5. 构建校验使用 esbuild 依赖清单确认正式入口不引用 `android/preview/`；打包只同步正式 dist，候选 APK 中不得包含预览入口或夹具。静态引用检查覆盖预览模块；构建通过仍不代表其模拟行为是真实业务结果。

阶段 0 出口：固定场景能加载真实页面、正式构建排除预览、当前安装包与源码基线可区分；无需连接手机或覆盖安装。

### 阶段 1：基础样式与返回链路

完成 A、B 的共用部分；先用本机人设、新会话、素材阅读三种代表页面检查纵向表单、标题和返回规则，再批量迁移其他页。优先落实页面状态归属、应用级返回接口和草稿行为表，不在各页重复加确认。只做本机静态检查、原生编译及必要行为测试，不装中间 APK；原生返回、键盘和窗口主题的实际表现仍留到统一真机验收。

### 阶段 2：所有模块统一完成

完成 C、D、E。所有 17 项合并到同一候选版本后再做集中真机验收；不每改一页就重新打包、让用户操作手机。工作可以按模块拆分，但 `main.jsx`、共用 CSS 和原生返回各由单一负责人维护，避免并发覆盖。

### 阶段 3：构建前集中检查

- `npm --prefix android run check:ui`：未定义引用与桥接方法检查。它不是完整类型检查，也不替代视觉验收。
- 对新增／改变的行为补必要测试：DAO 先过滤再分页及旧调用兼容、来源加载失败与已有 ID 保留、活动页面状态所有权、返回与草稿行为表、已有精细时间保存、隐私文案映射。不为圆角、边距写镜像式测试。SQL 条件必须通过实际 Room 查询测试，不能只测预览替身。
- 运行受影响的既有测试；如果触及桥接协议／共享逻辑，跑对应 mobile 测试。草稿、提交待确认、切库隔离的现有回归保留。
- 使用阶段 0 的独立入口检查所有页面与 Web 层非敏感面板：中文／英文，浅／深色，320／360／390 宽度；至少检查 1.3 倍文字、长名称和错误状态。浏览器生成的 select／日期／确认窗口不作为 Android 原生窗口通过的证据。
- `npm --prefix android run android:debug` 统一生成候选 APK，记录实际 APK 路径、校验值与此次源码状态。静态引用检查、相关测试和构建通过后才覆盖安装。

### 阶段 4：一次完整真机巡检，汇总后处理回归

真机按报告原 15 组流程顺序执行，统一记录缺陷；除阻断后续检查的问题外，不中途改一项再构建一项。全部检查完成后统一修复遗留项，重建一次再验证受影响流程和公共控件。

## 7. 交付与完成标准

交付修复源码、候选 APK、F01—F17 关闭表、真机截图对照及未覆盖项清单；不自动发布 Release 或推送。

完成标准：

- 五项 P1 都有对应修复证据；关联素材读取、系统返回等行为不只靠截图判定。
- 其他十二项 P2 全部有落实位置和复验结果，不能用“页面已美化”合并略过。
- R01—R06 与范围收敛项均有对应行为／构建证据，尤其不能以“有返回按钮”代替启动失败可退出，以预览假数据代替真实查询，以浅色弹窗通过代替深色和生命周期验证。
- 原有功能能找到入口，来源／日期／关联／草稿／任务精度未丢失，切库不串数据。
- 无明显错位、横向溢出、主题下不可读的启用控件；正文和主要动作不被键盘遮挡。
- 受保护或无样本状态明确写未验，不宣称“全部通过”。若还有 P1 或核心流程待验，只交付待验候选版，不能标记验收完成。

预计执行顺序是“基础统一 → 全部模块 → 一次候选构建 → 完整真机巡检 → 汇总回归修复”，不是逐页反复改、构建、安装。本方案不承诺所有问题一次构建就结束，但避免没有新变化依据的重复构建和测试。
