## 验收过程中修复

- 补齐原生记录接口的来源、附件、日期依据、关联和文章状态，避免页面只收到标题和正文。
- 初次同步与增量同步修复设备身份、协议版本、数字游标和清单校验等接口不一致。
- 普通导入使用独立 `import` 活动，保持原作者与历史日期，不把旧日记计为今日写作。
- 导入原件与记录元数据在同一事务提交；保留原始 Markdown 文件。
- 备份包括库内历史、草稿、未同步操作及分支；登录凭据和模型 Key 不进入备份。
- 恢复会话不继承运行态；未完成请求转为中断，不自动产生模型费用。
- 合法长文的 SQLite 查询使用可容纳完整记录的游标窗口；避免正文尚在库中但读取报 `SQLiteBlobTooBigException`。
- 同步并发门闩允许工作线程释放，避免跨线程释放线程专属锁后后续同步被阻塞。
- 同一附件在当前正文与历史分支中的引用按复合身份分别保存，恢复不会误报重复或漏掉分支原件。
- 分享/打开附件使用独立缓存文件，只清理超过 24 小时的缓存，避免第二次分享破坏前一个接收应用尚未读取的 URI。
- 本机完整备份恢复持久保存请求编号、目标库身份和完成标记；进程中断后继续原任务，已完成请求可重放回执，不覆盖后续编辑。
- 恢复数据库暂不可读时保留现场；只有确证未提交才清理该恢复任务的临时数据库。注册表 v1→v2 索引声明与迁移一致。

## 正在验收

v4→v5 资料库迁移、v1→v2 注册表迁移、冲突与恢复故障注入等 34 项真机回归已通过。自动调度在不同系统省电策略下的可靠性、真实服务丢失后的多设备恢复仍需进一步真机验证。窄屏静态预览不替代软键盘和原生窗口的实际触摸验收。真实付费模型调用未获测试授权，本轮只使用模拟模型。

长程真机测试曾多次被设备系统冻结：测试线程 `wchan=do_freezer_trap`，设备处于 Dozing。超时/强制结束的这些运行不计为通过；需要保持手机解锁、应用在前台后重跑。调试工程增加了仅显示通用测试状态的前台 Activity（不进入 release），不修改系统省电或锁屏配置，也不解除锁屏。

再次解锁并保持亮屏后，测试进程曾仍被冻结；已确认其内核 cgroup 报告 `frozen 1`。用户将应用省电策略设为无限制后，后续真机测试正常运行。测试期间曾尝试的调试状态页在该设备启动超时，后续测试已不依赖该页面。
