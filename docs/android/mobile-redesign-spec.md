# 拾文 Android 页面结构与交互方案

日期：2026-11-07。状态：**用户已选定本轮第 3 个视觉方向「专注工作台」；尚未实施。** 具体步骤与阶段验收见 [执行计划](mobile-redesign-execution-plan.md)。

这份文档回应真机审查发现的布局错位、信息堆叠、资料库长期占位、控件主题不一致、键盘与横屏遮挡。它不代表现有版本已经达到这些要求。

沿用 [页面与状态设计](ux-flows.md) 的资料归属、完整副本、来源与同步语义，以及 [原有菜单能力矩阵](dsh-menu-capabilities.md) 的能力边界。本文细化页面组织与呈现；不调整同步协议、不替换 Agent 运行时，也不因界面精简删除现有能力。本轮视觉依据为 [专注工作台](assets/mobile-redesign-selected.png)，原 [首页概念图](assets/selected-home.png) 保留作历史参考。

## 1. 设计目标与取舍

用户打开手机应能立即记录、继续对话或阅读。当前资料属于哪个库、AI 在哪里运行，需要看得明白；连接地址、版本哈希和协议细节不需要一直出现。

- 正文优先：记录、阅读和对话占据主要空间。
- 一页一个主要任务：列表不同时展开新建表单，设置不同时展开全部配置。
- 信息按需出现：正常状态保持简短；失败、待确认与冲突提供具体入口。
- 保持内容密度：减少大标题、重复说明、卡片嵌套，不靠缩小文字塞内容。
- 同一控件只有一套尺寸与状态规则，兼容原生安全弹窗和系统栏。
- 不增加新的总控页、全局状态框架或重复导航层。

## 2. 导航与页面层级

### 2.1 五个主入口

| 主入口 | 默认页面 | 主操作 | 次级入口 |
| --- | --- | --- | --- |
| 对话 | 当前会话；首次为空会话引导 | 发送消息 | 直接记录、会话历史、助手选择 |
| 素材 | 当前库素材列表 | 新建记录 | 搜索、筛选、回收站 |
| 创作 | 当前库文章列表 | 新建文章 | 搜索、文章状态筛选（有接口支持时） |
| 回顾 | 当前库最近使用的时间范围 | 查看某一天的明细 | 切换范围、统计口径 |
| 设置 | 分组条目列表 | 进入某项配置 | 关于与诊断 |

“更多”不再重复对话、素材或其他已有主入口。原本其中独有的工具并入设置对应分组；“创建自己的插件”保留在插件页，实际执行仍由 DSH 服务会话承担。

### 2.2 主页面与子页面的框架

| 页面类型 | 顶部 | 底部 | 滚动规则 |
| --- | --- | --- | --- |
| 五个主页面 | 一条紧凑栏：页面名称、当前库名称入口、必要操作 | 五栏导航 | 内容区域滚动，页面之间各自保存位置 |
| 会话 | 当前库入口、历史/新会话；下方一行助手与执行位置 | 输入区、五栏导航 | 消息滚动，输入区保持可见 |
| 阅读详情 | 返回、紧凑标题/库名、更多 | 可选轻量“编辑”操作；不显示五栏导航 | 长正文独立滚动 |
| 记录/文章编辑 | 返回、保存；库名作为次要归属文字 | 正文工具条按需显示；不显示五栏导航 | 编辑区可滚动，光标可见 |
| 设置子页 | 返回、页面名称；远端页附服务名称 | 不显示五栏导航 | 新进入从顶部开始，返回恢复上级位置 |
| 短选择面板 | 标题、关闭 | 面板内必要操作 | 内容过多时面板内部滚动 |

主页面顶栏中的资料库入口是短名称与箭头，不是另一张常驻卡片；超长名称省略，打开面板可读全称。编辑中仅显示归属，不直接切库；返回时按既有草稿规则处理，再切换。

所有子页通过页面返回和 Android 返回手势得到一致结果。返回优先关闭键盘，再关闭面板，再返回上一级；有未保存内容时遵循实际草稿能力，不显示虚假的“已保存”。

## 3. 资料库切换与服务选择

### 3.1 资料库底部面板

入口：点击任一主页面顶栏的当前资料库名称。

内容顺序：标题“切换资料库” → 资料库列表 → “新建手机资料库” → “连接服务资料库” → “管理资料库”。

每个列表项最多默认两行：第一行名称与当前选中标志；第二行服务昵称或“仅本机”，再加必要同步摘要。例如“家里的电脑 · 已同步”或“办公电脑 · 离线 · 2 条待同步”。离线与待同步属于不同状态，不互相替代。不能确认数量时不显示 0。

- 列表按资料库身份去重，不能把两个连接地址画成两个同库副本。
- 多个库同名时用服务昵称帮助区分；详细身份放到库详情中。
- 点选已有本地库后关闭面板，刷新当前主页面内容；不自动发送消息、复制资料或改写草稿归属。
- 正在初始化的库明确显示“初始化未完成”；可读范围按实际能力，不标为完整副本。
- 面板最大高度受可用窗口限制，不能挤出屏幕。很多资料库时在面板内滚动。

### 3.2 资料库与服务节点不是同一个选择器

资料库决定“看和写哪份资料”；服务节点决定“连接哪台机器、远端 Agent 在哪里运行”。两者分别管理。

默认当前库详情只列与其实际关联的服务。切到另一台服务的远端助手时，必须明确显示目标服务及其资料归属；如果与当前库不同，提供“前往该服务的资料库”选择，不能继续用旧库名称伪装成同一上下文。实施时复用已有身份核对与会话隔离，不在 UI 新造一套绑定规则。

## 4. 对话：一个窗口，两种执行位置

### 4.1 页面从上到下

1. 紧凑顶栏：当前库名称；会话历史、新会话各一个入口。
2. 助手行：“皮皮 · 手机助手”或“皮皮 · 家里的电脑”，点击选择执行位置与可用助手。
3. 消息区域：用户消息、助手回复、工具进度、必要审批、保存回执。
4. 输入区：输入正文、附件/引用入口（仅在能力可用时）、发送；“直接记录”为明确独立的次级动作。
5. 底部导航：仅在键盘关闭且当前为根页面时显示。

不再并列两个大模式按钮，不再重复显示多个“新会话”，不常驻刷新按钮、工作区修改权限或“将原文保存到素材”的复选框。

### 4.2 空会话与正常会话

空会话用一行“今天，记下些什么”及短提示即可。不展示大统计卡片或功能宣传。消息出现后收起欢迎内容，把空间归还给对话。

历史入口打开独立会话列表，提供搜索、最近会话、执行位置与运行状态。返回会话后恢复阅读位置；新消息到来时若用户正在读旧内容，显示“有新消息”，不强行拉到底。

新会话需要工作区、Agent 预设时，打开独立配置页：字段逐个纵向排列，底部只有一个创建按钮；服务器默认值清楚展示。配置完成后仍回到同一个对话窗口。

### 4.3 直接记录与 AI 对话

- 直接记录：将当前输入带入记录编辑器，先不发给模型。保存成功后回到原位置，并显示简短保存结果。
- 发送：只发送到当前明确选定的助手/位置，不默认把每条对话都算成素材。
- 保存某条消息：在消息操作中选择保存，展示类型与来源确认；用户原文、AI 回复、混合整理分别保留原有来源语义。
- Agent 工具保存成功：显示小型回执，包含记录标题、实际保存位置、来源与同步摘要；“查看”进入详情。
- 远端工具只确认服务端保存时，不能显示“已保存到手机”。

### 4.4 任务、工具与中断

工具运行显示一行进度摘要，点开看步骤；需要审批时以明确操作区呈现，不藏进更多菜单。长工具结果默认折叠，但不隐藏失败原因。

连接中断显示“连接中断，执行状态待确认”，重连后查询原任务，不把网络断开当作任务终止。停止操作根据实际回执更新；不会为简化界面移除既有审批、停止与恢复能力。

## 5. 素材与创作列表

两页复用同一套列表规则：顶栏 → 搜索 → 紧凑筛选入口 → 平铺列表。每行默认标题与日期；素材可增加短类型，文章只显示真实存在的状态。待同步/冲突只有需要关注时出现。

标题允许两行，日期在独立次要行，不与标题争宽。行之间用分隔或空间组织，不给每条记录加完整外框。不常驻“大段页面说明”“已加载 30 条”等实现信息；底部加载状态有必要时才显示。

筛选面板按现有查询能力提供类型、日期、来源。接口没有支持的筛选不得在视觉稿中伪装可用；文章若只有一种类型，删除无效的“全部类型”。筛选后无结果要提供“清除筛选”，请求失败则提供“重试”，不能共用一个空列表文案。

导入移到设置“导入与备份”，列表更多菜单可以提供快捷入口；回收站从更多进入，不长期占据筛选区。

## 6. 阅读、记录与创作编辑

### 6.1 阅读页

正文前默认只显示标题、内容日期、必要类型/来源、所属库。完整的创建时间、更新时间、日期依据、创建设备、来源说明与原始文件进入“记录信息”。日期说明不使用接近背景的文字颜色。

正文使用可读 Markdown 排版，标题、列表、引用、代码块各有样式；保存仍遵循现有 Markdown 数据格式，原始文件入口保留。图片与原件的呈现按记录实际内容与已有导入规则，不在 UI 改造中重新清洗历史资料。

更多菜单承接分享、导出 Markdown、复制到其他库（如已有能力）、删除。删除与普通操作在样式和确认语义上明确区分，不把删除按钮单独留在正文上方。

### 6.2 记录编辑页

默认进入即可书写。标题可选，正文在首屏可见；日期、类型、来源作为紧凑元信息入口，展开才显示完整字段。

新记录默认类型与来源遵循用户实际操作：直接书写是自己书写；AI 整理不因为通过工具保存而变成原创，也不因为由 Agent 代记就自动算作 AI 内容。

保存入口固定在简洁顶栏，点击后显示真实进行状态。保存失败保留正文并就地提示，不离开编辑器。未确认持久化前不能显示保存成功；退出行为继续使用既有草稿机制。

### 6.3 创作编辑与发布前检查

正文编辑为默认；预览、关联素材、文章状态、发布前检查通过工具入口进入独立页或面板，不把桌面多列压到手机。

发布前检查逐项呈现已有检查能力的结果、具体位置与修正入口。检查通过、已定稿、已发布是不同状态，不能互相推断。缺少能力时明确标为待接入，不增加没有后端的“全部通过”按钮。

## 7. 回顾

顶栏标明当前库。时间范围用一个紧凑入口显示当前选择，展开支持今日、近 7/14/30 天及自然月；自然月选择器不能要求逐日翻页。

页面顺序：时间范围 → 四个核心指标 → 写作与收集趋势 → 每日明细。四项指标保持两列，放大字体时可转为单列。趋势可用文字摘要和数据明细读取，不只靠颜色区分。

统计口径在“如何统计”中解释。历史导入、原创写作、AI 内容与同步日不混算；初次同步未完成时明确显示统计覆盖情况。此轮只调整显示，不改变既有统计口径。

## 8. 设置首页：分组条目，不展开表单

| 分组 | 条目 | 默认摘要 |
| --- | --- | --- |
| 常用 | 服务与同步 | 当前库最近同步状态；必要待处理数 |
| 常用 | 模型 | 手机当前模型名称或未配置 |
| 常用 | Agent 与记忆 | 当前使用的人设来源；必要待确认数 |
| 工具 | 插件 | 选定服务或尚未连接 |
| 工具 | 自动化任务 | 选定服务；不把未知数量显示成 0 |
| 工具 | 外部接入 | 已连接服务名称 |
| 工具 | 导入与备份 | 无需长摘要 |
| 工具 | 分享收件箱 | 有待保存项目时显示数量 |
| 应用 | 存储与资料库 | 本机占用摘要 |
| 应用 | 外观与语言 | 跟随系统、中文等当前值 |
| 应用 | 关于拾文 | 当前真实应用版本 |

顶栏不再常驻 Android 与版本号。正常状态摘要一行，异常摘要最多两行；进入详情看原因和处理方式。没有节点时保留相关入口，打开后给出“连接服务”路径，手机本地功能仍正常可用。

## 9. 设置子页与 DSH 能力保留

### 9.1 服务与同步

默认显示当前库的同步摘要、手动同步，以及自动同步/后台同步偏好。库详情包含实际关联服务、待处理冲突、最近同步结果；进度细节按需展开。

“管理服务”进入节点列表，支持自定义名称、地址、登录、检查连接、移除连接。密码在原生安全表单内输入；前端只接收脱敏状态。新连接后核对库身份，明确初始化进度与完整性。

“查看冲突”必须进入真正的列表页面或把结果滚到可见位置，不能点击后只在屏幕下方插入内容。冲突详情使用手机版/服务端版切换或上下对照，支持现有合并动作；不在手机强做两窄列。

初始化、恢复、更换协调服务放入“高级管理”，保留完整能力。入口说明其用途，执行前展示影响范围；不能因菜单精简而绕过已有核对步骤。

正常无错误时不显示“最近错误：null”。时间显示本地易读格式，详细时间与原始标识可在诊断中查看。内部角色值转换为“仅本机”“已连接同步服务”等用户语言。

### 9.2 模型

先展示手机模型摘要，再进入编辑。名称、接口地址、模型标识与密钥使用一致的标签和输入规范，兼容自定义服务商，不强制下拉选择预设代理商。

原生安全窗口需要适配深浅主题、键盘和字体，保持既有凭据保护。截图受保护时用无真实凭据的测试环境或现场目视验收，不能为截图关闭生产凭据保护。

### 9.3 Agent 与记忆

先选管理范围：手机人设，或明确命名的服务器助手。每个范围显示当前状态，再分为“身份与性格”“用户偏好（支持时）”“已确认记忆”“待确认记忆”。

每份文档独立编辑，标签在上、输入在下。用户名称与技术文件对应：身份 IDENTITY、性格与原则 SOUL、用户偏好 USER；仅在有真实读写能力的范围展示编辑。远端没有 USER 写接口时不画可保存表单。

记忆列表先显示简短正文与分类，详情提供修改/删除；候选记忆提供接受/拒绝。人设同步的版本信息折进详情，不默认打印哈希。界面明确“修改影响后续会话”等已有生效规则。

### 9.4 插件

默认已安装列表；发现、安装、服务器插件配置为次级入口。插件条目显示名称、短说明、版本与真实状态；详情支持既有版本查看、更新、启停、卸载等能力。

安装输入与确认独立呈现，完成后查看真实结果。服务器设置、密钥安全编辑、插件创建入口保留。某服务不支持的能力只标在对应入口，不用“此服务不可用”暗示整台服务离线。

技能、MCP 只通过已经接通的 DSH 管理能力展示；不能把人设同步描述为已同步全部工具运行时，也不能用本次设计承诺通用 Skills/MCP 管理已实现。

### 9.5 自动化任务

默认任务列表，状态筛选在顶部；新建/编辑进入独立单列表单。任务详情包含执行内容、时间规则、时区、状态与历史入口。保留已有重复规则、手动执行、启停、版本冲突处理能力；自然语言生成规则仅在已有能力支持时提供。

空列表只有一条说明和新建入口。清理已结束任务放在更多，执行影响通过原有确认流程说明。长期任务由实际服务执行，不以移动端动画代替真实状态。

### 9.6 外部接入

默认已授权客户端列表与简短服务状态；新建客户端打开单独表单，先名称再权限范围。按钮使用“创建访问凭据”，不用“通过原生窗口创建”。

凭据仍只在原生安全窗口展示，支持范围内的撤销等管理保留。区分服务端地址与手机能访问的地址；不要把回环地址包装成可直接连接的局域网入口。

### 9.7 导入、备份、分享与存储

导入与备份分为导入 Markdown、备份当前库、从备份恢复三个清楚入口。恢复时再选择回原库或作为新库，并显示对应影响。正文不默认显示幂等、请求编号等实现术语。

分享收件箱显示待保存项目，点开后确认目标库、内容、来源与类型；只收到链接时不得显示已抓取全文。保存成功后根据真实回执移出待处理列表。

存储页展示当前库与附件占用、本机剩余空间、资料库改名和临时缓存清理。清理缓存、移除连接、删除记录仍是三个不同操作，不能合成“清理资料”。

## 10. 全局状态与文字规范

| 情况 | 默认呈现 | 操作 |
| --- | --- | --- |
| 仅本机库 | 仅本机 | 管理同步 |
| 正常同步完成 | 已同步，必要时显示时间 | 查看同步详情 |
| 服务离线且本地完整 | 离线可用；有待上传时显示实际数 | 连接设置/手动重试 |
| 初次同步 | 正在下载，进度可查；未完成不能叫完整副本 | 查看进度 |
| 登录失效 | 需要重新登录；本机资料仍保留 | 重新登录 |
| 同步冲突 | N 条待处理 | 打开冲突列表 |
| 写入结果待核对 | 正在确认保存结果 | 查看状态，不诱导重复创建 |
| 查询失败 | 原因与重试，不清空已有正文冒充无内容 | 重试 |
| 不支持某能力 | 对应入口说明需要更新服务或尚未支持 | 查看说明 |
| 表单无变化/内容空 | 按钮禁用，必要时给简短原因 | 保持编辑 |

错误靠近触发动作；跨页任务通过相应详情页持续可查。不把每条正常状态都做成彩色通知条。状态必须包含文字，不能只用红点、绿点或颜色。

## 11. 控件与布局规范（待视觉稿校准）

下表是实施约束的初始值，不是已选视觉稿的像素定稿。

| 项目 | 规则 |
| --- | --- |
| 页面边距 | 常规 16 逻辑像素；窄屏保留阅读空间，不层层叠加卡片内边距 |
| 顶栏 | 默认约 56dp；大字体可增长，不靠固定高度裁字 |
| 正文 | 默认约 16sp，长文行高约 1.65；系统放大可生效 |
| 标题 | 页面 20–24sp；子页不叠加品牌大标题 |
| 次要文字 | 通常 13–14sp，保持可读对比度 |
| 触控区 | 主要交互至少 48dp；小图标允许视觉小、热区足够 |
| 按钮 | 同层同高；明确主、次、文字、危险四种，不混用不相干圆角 |
| 输入 | 标签独立一行；同一套圆角、边框、焦点、错误、禁用态 |
| 选择 | 短选项统一选择面板；复杂选择进入独立页，不裸露深底 HTML 下拉 |
| 开关/复选 | 偏好用开关，集合选择用复选框；品牌色与系统主题协调 |
| 长文字 | 名称可省略但可看全；表单、正文、错误内容允许自然换行 |
| 容器 | 先间距和分隔线，再背景分组；不把卡片套进卡片 |
| 深浅主题 | 语义色统一；覆盖正文、表单、弹窗、原生状态栏和导航栏 |
| 焦点 | 清晰可见，圆角与控件一致；不移除焦点提示来掩盖样式问题 |

## 12. 键盘、大字体、横屏和可访问性

- 键盘打开：收起根页面底部导航、欢迎文案和非必要工具栏；保留紧凑归属/助手信息、消息区、输入及发送。输入区整体位于键盘上方，不能只保证文本框可见而截住按钮。
- 多行输入：随内容增长到可用区域的合理比例后内部滚动。不能用固定大高度把消息区挤没，也不显示网页式拖拽角标。
- 编辑器：当前光标、保存入口与错误提示可到达；返回先收键盘，不直接丢弃编辑。
- 大字体：至少覆盖 100%、130%、150%、200% 的正文和控件检查；窄空间改成纵向排列，不能把中文拆成单字列或缩小字体抵消系统设置。
- 横屏：缩短顶栏与辅助区域；输入、操作和导航之间有明确高度分配。若需要隐藏非必要导航，应保留返回入口。
- 小屏：以 360×640、390×844、412×915 逻辑视口检查；长名称、英文、日期与中文都要测试。
- 屏幕阅读：图标有名称，页标题和表单标签可识别，焦点随面板开启/关闭合理转移，错误和任务状态变化能被感知。
- 禁用态不等于低到看不清；普通次要文案也不能接近背景色。深色状态栏图标需真实验证，不能仅检查网页部分。

## 13. 功能去向与现有实现对照

| 现有模块 | 新位置/呈现 | 保留边界 |
| --- | --- | --- |
| main.jsx 全局资料库区 | 紧凑顶栏 + 切换面板 | 当前库上下文与切库流程 |
| ChatPanel / RemoteChatPanel | 同一对话框架、不同执行上下文 | 手机任务与 DSH 会话仍分别运行 |
| RecordPanel / MarkdownView | 列表、阅读、编辑分开 | 保存、来源、原件、Markdown 与删除语义 |
| ReviewPanel | 范围入口、指标、趋势、明细 | 原统计口径 |
| SettingsPanel | 分组入口 | 不丢失原有配置路径 |
| LocalAgentProfilePanel / AgentSettingsPanel | 管理范围 → 文档/记忆子页 | 各自支持的字段与真实写权限 |
| ManagementPanel / PluginDetailsPanel | 插件与任务列表、详情、编辑 | 服务能力检测、任务结果、版本与配置保护 |
| LibraryReplicaPanel / RecoveryPanel | 服务与同步、冲突、独立高级恢复页 | 完整性、同步偏好、身份核对与恢复确认 |
| LibraryTransferPanel / ShareInboxPanel | 导入备份、分享收件箱独立页 | 原文件操作、内容确认和保存回执 |

这是职责映射，不要求一行拆成一个新文件。优先复用现有数据与动作，抽出少量真正共用的页面框架、表单行、选择面板和状态组件；不引入通用页面生成器、另一套路由状态库或重复缓存。

## 14. 设计与实施顺序

1. **结构设计（本文）**：页面职责、入口、上下文、返回与状态规则。
2. **视觉选择（已完成）**：用户选定第 3 个方向「专注工作台」，涵盖对话、资料库面板和设置首页。
3. **关键页面扩展**：把选定方向扩展到列表、阅读、编辑、回顾、Agent、插件/任务表单，并补深浅主题、键盘状态。不是只定首页就开始全面套样式。
4. **实现共用框架与控件**：先解决固定区域、滚动位置、键盘、字段纵向排列和系统主题；保持资料与服务层不变。
5. **迁移日常流程**：对话、素材、创作、回顾；随后迁移设置与全部管理子页。开发期间逐组进行构建、自动化测试和隔离界面检查。
6. **统一真机验收**：按用户最新要求，全部页面完成后再集中验证真机行为、修复与复验。下面清单逐项记录通过、失败或实际阻碍，不把截图、单测或编译通过等同于交互验收；实际设备项目在此之前保持待验。

目前完成第 2 步，已补充 [详细执行计划](mobile-redesign-execution-plan.md)，未进入应用实现。

## 15. 验收清单与退出条件

| 组别 | 必查状态 | 通过标准 |
| --- | --- | --- |
| 框架与导航 | 五主页面、各子页返回、多次进入、长列表 | 无继承错误滚动；返回可恢复上级位置；当前归属清楚 |
| 资料库 | 多库、同名、仅本机、离线、初始化、长名称 | 不重复同库，不误标完整，面板不越界 |
| 对话 | 空态、已有消息、工具、审批、保存回执、断连 | 主操作明确，状态与实际位置一致 |
| 输入 | 短文、长文、键盘开关、横屏 | 光标与全部操作可见可达，没有导航覆盖 |
| 记录/文章 | 新建、编辑、长文预览、原件、删除提示、分享 | 正文优先，来源不误改，返回不丢草稿 |
| 回顾 | 五种范围、自然月、空数据、未同步完 | 指标可读，范围正确，不误示完整统计 |
| 人设与记忆 | 手机/远端、文档编辑、候选与已确认记忆 | 无字段错位，写入范围清楚，保存反馈可见 |
| 插件 | 列表、详情、版本、安装进度、配置、能力不足 | 操作可达，真实状态清楚，不因失败变成空态 |
| 自动化 | 空列表、已有任务、各规则、时区、历史、错误 | 表单可读，任务与新建分开，操作反馈可见 |
| 外部接入 | 列表、权限表单、安全弹窗、撤销提示 | 主题统一，不暴露凭据，不误导地址用途 |
| 同步/恢复 | 手动/自动、冲突、离线、登录过期、恢复各阶段 | 结果入口可见，不显示 null/原始内部枚举 |
| 数据工具 | 导入、备份、恢复选择、分享空态/有内容、存储 | 操作含义可区分，确认页明确目标库 |
| 适配 | 深浅、四档字体、三种竖屏、横屏、中文/英文 | 不裁字、不遮挡、不靠缩字解决布局 |
| 可访问性 | TalkBack、焦点、触控、状态说明 | 非颜色单一编码，图标和字段可识别 |

真实资料上的删除、恢复、插件安装和凭据创建不是视觉检查的默认操作。需要这些状态时使用隔离测试库/节点与无真实密钥的配置；只读真机检查和隔离交互验证分别记录。任何截屏保护或缺少测试条件的项目列明阻碍，不写成已通过。

## 16. 本方案自检

- 功能完整性：五个主入口与 DSH 管理入口均有去向；模型、插件、任务、来源、原件、分享、冲突、恢复未被 UI 减法删除。
- 上下文完整性：资料库和执行服务分开表达；保存位置、内容来源与同步状态没有混用。
- 信息层级：高频内容留在主流程；低频配置进入子页，技术标识进详情。
- 实现复杂度：仅调整展示与导航组织，复用现有 bridge/Repository，不扩大同步与 Agent 改造范围。
- 已选视觉方向，尚需补齐其余页面与状态，并落实精确色值、字号、圆角和图标规则；三个已选视图不代表所有页面已有完成稿。
