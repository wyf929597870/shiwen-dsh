# Mobile sync P1: server write-boundary audit

Read-only review of the current source. No personal library contents were opened. The production store is still `plugins/library/legacy/store.mjs`; the mobile v1 protocol contracts and coordinator under `tests/support/mobile/` are a draft/test model, not a production write path.

## Current sync-specific gap

`contracts/mobile/v1/schema.mjs` defines strict record/activity/operation/push/setup/receipt payloads, but labels itself P0 draft and says it is not advertised by the running service. The coordinator in `tests/support/mobile/coordinator.mjs` is explicitly a test-only model and is not connected to `createStore`. The record model covers current markdown, source segments, date, source IDs, attachments, and tombstone state; it does not yet define the actual durable event/outbox writer in the production SQLite library. A mobile profile snapshot is a separate read-only RPC and does not close that write gap.

The minimal complete boundary is one library-owned transaction that applies one validated operation and records all of the following together: canonical current row, revision/version, source/provenance segments, article-material links, date/import metadata, tombstone, operation fingerprint/receipt, and a monotonically ordered library change cursor. Attachment bytes remain staged separately, but the operation must remain blocked until referenced hashes are verified. The server should return the receipt only after the transaction commits. No production code currently centralizes all those writes under a sync event cursor.

## Recommended implementation order

1. **Choose sync scope and stable change envelope.** Specify which entities are portable records versus node-local DSH sessions, model/provider settings, external-client tokens, and transient runs. Keep profile snapshots separate from credentials. Bind each operation to library ID, epoch, device ID, operation ID, request fingerprint, base revision/version, record ID, and local generation.
2. **Add one store-owned atomic apply primitive.** Validate on the host, then apply create/update/delete/restore and its side tables plus receipt/outbox event in one SQLite transaction. Make same operation ID + same fingerprint replay the recorded receipt; same ID + changed payload must fail. Preserve existing `save`/`updateRecord` business validation by calling internal transaction-aware helpers rather than duplicating content rules in routes.
3. **Route every portable write through that boundary.** Start with record create/edit/delete/restore and date changes. Migrate `saveDsh`, article/source links, profile/memory changes, and external writes next. Every path should either emit a canonical sync event in the same transaction or be declared node-local. Avoid direct side-table `UPDATE`s that bypass revision/outbox.
4. **Separate blobs from metadata with dependency receipts.** Stage chunks and verify byte length/hash before the record operation references them. Make the content operation blocked until all blob dependencies exist; clean unattached staging objects after a bounded retention period.
5. **Implement pull cursor and snapshot/epoch reset.** Deliver committed events in stable order, let devices persist applied and complete cursors separately, and require a fenced baseline/epoch change after whole-library restore or initialization. Include tombstones and old-version/conflict ancestry needed for recovery.
6. **Only then expose mobile push/pull routes and exercise multi-node faults.** Test duplicate replay, same-ID altered payload, crash before commit, lost ACK after commit, attachment interruption, concurrent stale edits, date correction, delete/restore, and restore epoch reset against temporary SQLite stores—not only the coordinator test double.

This ordering keeps transaction correctness inside the library and transport concerns in the HTTP/session layer. The highest-risk first gap is date/metadata and tombstone writes bypassing a change cursor; broadening the protocol before a single SQLite commit boundary exists would allow devices to report “synced” while auxiliary state differs.
