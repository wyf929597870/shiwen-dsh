# 拾文 DSH 桌面版实施方案（历史规划）

状态：实施中。本文记录目标与验收条件；当前完成情况以项目 README 为准，不能将目标视为已完成。

更新日期：2026-11-05。

## 1. 已确认的产品路线

基于 DSH 原生对话和会话管理构建拾文桌面客户端，统一使用拾文现有的深灰、薄荷绿、紧凑排版与 Logo。业务能力通过插件接入，包括记录、知识库、素材整理、创作和回顾。

整个应用只有一套对话系统。首页就是原生 Agent 对话；素材和文章页面里的“讨论”进入同一会话系统，附带明确选中的记录引用。编辑器可以有返回关联会话的入口，但不再实现第二套聊天组件、消息存储或 Agent 调度器。

首个交付平台是 Linux x64，目标为可安装的 `.deb` 和可运行的解压目录。Windows 保留架构兼容性，正式支持须在 Windows 上构建与验证，不能以 Linux 构建成功代替。

## 2. 当前代码核对结果

核对基线：本地 `deepseek-harness` 的提交 `8bd073392eef6f54e921a093b95076248eb08cbb`，包版本 `0.2.2-alpha.3`。后续升级必须重新核对接口与打包要求。

| Linux 打包 | `apps/desktop/scripts/package-target.ts` 的目标只有 `mac-arm64`、`mac-x64`、`win-x64` | Linux 是需要完成的适配工作，不是上游已验证能力 |
| 平台策略 | `apps/desktop/src/main.ts` 部分更新策略仅接受 macOS/Windows，其他位置已有 Linux 分支 | 分别检查启动、更新、托盘、文件选择器、原生依赖；不能只增加一个打包目标 |
| 主题扩展 | `packages/client/ui-theme` 的 `overrideTokens` | 使用有深浅两套值的主题覆盖，保留原生主题设置和字体设置 |

| 运行与会话 | DSH 原生 Agent、Session、工具和压缩插件 | 不搬入旧版的 ToolLoopAgent、自写会话摘要或重复消息状态 |

只确认上述扩展点存在，尚未验证完整装配和 Linux 桌面运行。

## 3. 工程组织与上游维护

新工程目录为 `shiwen-dsh`，与已推送的 `shiwen` 分开。原有项目继续作为可运行版本和业务逻辑参考。

建议目录：

```text
shiwen-dsh/
  upstream/dsh/             固定提交的上游源码，由 Git submodule 管理
  patches/desktop/          Linux、品牌及发行配置的必要源码补丁
  profiles/                拾文的 DSH profile、bundle 和组合配置
  plugins/
    theme/                 主题、品牌、首页展示
    library/               记录与素材的数据服务
    agent-tools/           Agent 可调用的业务工具
    workbench/             素材、文章、回顾页面和对话动作
    personal-context/      角色、用户偏好和长期记忆的业务策略
  scripts/                 构建、装配、测试、Linux 打包
  tests/                   插件、完整运行链路和桌面验证
  docs/                    设计、数据格式、升级记录
```

上游源码保持固定基线。构建时在派生目录应用记录在案的补丁，避免直接改安装后的 `node_modules`。优先通过配置、主题和界面扩展实现需求；仅桌面发行和确实缺失的界面位置允许增加小范围源码补丁。补丁须说明目的、涉及文件及升级时的验证方法。

DSH 原生客户端使用 React。新业务页面按它的组件和插件约定实现；旧版 Vue 页面作为视觉与交互参考，不在原生客户端中再嵌入完整 Vue 应用。纯数据处理逻辑经核对后可复用。

新安装使用独立的 Electron userData、DSH_HOME、profile 和资料库目录。重装保留用户数据；初始化不得自动导入或覆盖旧拾文资料。具体默认目录由桌面统一提供，插件不自行猜测系统路径。

## 4. 页面和交互范围

### 首页与对话

- 沿用原生会话列表、消息渲染、流式输出、工具过程、审批、提问、停止和恢复。
- 调整品牌、首页文案、配色、字体、间距和输入区视觉，使其符合拾文的创作者工作台气质。
- 增加选择资料作为上下文的入口，清楚展示当前引用及其版本，不默认把整库塞进上下文。
- 消息增加“保存原话”“保存为素材”“转为文章”等动作；成功后展示可打开的结果。
- 从素材或文章进入讨论时，显示关联会话供继续，或显式新建会话；不得静默串入不相关对话。
- 流式输出中的不完整消息不能被误当作完整归档结果；保存节选应明确标记。

### 资料与素材

- 支持日记、想法、自由书写、外部素材和 AI 讨论资料，保留来源分类、日期与标签。
- Markdown 作为内容格式保存，默认渲染标题、列表、引用等；日期和标签单独展示。
- 原始文件与整理正文分开保存，原件不可被 AI 整理覆盖。
- 提供检索、类型与日期筛选、来源详情、编辑和历史版本。
- 旧库的清洗分类与排除规则从既有记录迁移，不重新推断用户已经确认的决定。

### 创作

- 文章项目具有关联素材、草稿/定稿状态、Markdown 正文和版本。
- 保留可读编辑体验与 Markdown 导出；复用可验证的旧业务规则，不强行复用 Vue 组件。
- AI 生成或修改文章先形成可查看的结果，覆盖既有正文时展示差异并确认。
- 发布前检查结构、来源和可能的私人信息；通过检查与实际发布是不同操作。
- 已发布历史文章迁移为定稿，只迁移清洗后的正文，不恢复被排除的图片和附件。

### 回顾

- 支持当日、近 7/14/30 天及自然月。
- 分开统计个人书写、收集素材、AI 整理和文章产出。
- 内容所属日期、导入时间、收集时间和编辑时间分别存储，不能相互代替。
- 历史导入不计为当天新写；未知日期保留待确认。
- 字数存量、编辑增量分别命名；不能把当前正文总字数标成某日新增字数。
- 页面与 Agent 查询使用同一个统计服务，可从汇总追溯到记录。

### 设置

- 复用 DSH 原生模型和插件设置能力，沿用拾文中英文界面需求。
- 代理商名称、Base URL、模型 ID 自由填写；协议选择与模型路由选择可保留必要控件，不以固定代理商下拉限制输入。
- 密钥使用 DSH 凭据机制的适当 provider；不得放入前端配置、资料正文或日志。
- 增加关闭窗口时“退出程序 / 最小化到托盘”选项，并在 Linux 验证实际行为。无可用托盘时不能让应用无入口地隐藏。

## 5. 插件职责与数据归属

| 插件/模块 | 负责 | 不负责 |
|---|---|---|
| DSH 原生运行层 | 模型路由、Agent 循环、原生会话日志、工具执行、上下文压缩、运行生命周期 | 拾文记录分类与统计规则 |
| theme | 深浅主题、Logo、首页品牌展示、紧凑视觉 | 改写 Agent 状态或业务数据 |
| library | 记录、来源、原件、标签、日期、版本、草稿、文章关联、统计 | 复制 DSH 消息日志充当另一套会话 |
| agent-tools | 参数校验、调用同一业务服务、结果回执、来源和执行关联 | 自写模型循环或直接绕过业务服务写数据库 |
| workbench | 业务页面、消息动作、记录引用、查看工具执行结果 | 第二套聊天状态机 |
| personal-context | 角色/风格、用户偏好、长期记忆管理和注入策略 | 替代 DSH 历史日志、压缩器或资料库 |

记录通过 DSH Session ID、消息/事件 ID、原始文本快照及记录版本建立来源关系。删除或导出会话后，已归档资料仍有明确出处与独立正文；会话日志是对话事实源，资料库保存的是用户主动沉淀的内容。

跨存储保存不假设存在跨库事务。业务写入记录操作 ID 和来源，事务提交后才返回成功；相同操作重试返回原结果。不得在数据库尚未落盘时仅靠模型回复声称“已保存”。

## 6. Agent 操作规则

提供记录检索、原文读取、保存日记/想法/素材、创建文章、文章修改提案及回顾查询工具。页面按钮和 Agent 工具调用同一业务服务。

- 检索、读取、统计：根据用户当前请求直接执行。
- 用户明确要求新建或保存：目标清楚时直接保存并提供可打开的回执；必要字段不清楚时由原生提问交互补齐。
- “帮我记一下”写入记录；“记住我的偏好”进入记忆流程，两者不能混用。
- 保存原话应从指定原始消息取得文本，不依赖模型逐字转述；AI 整理作为独立内容，标明混合或 AI 来源。
- 修改已有正文：带版本校验，展示修改结果；覆盖或冲突需明确处理。
- 批量删除、覆盖导入、对外发布：展示对象和影响后确认，不用模型推断代替用户授权。
- 外部文章和历史消息里的指令不能作为写入授权；不要用固定中文短语正则充当自然语言意图判断。
- 模型选取的引用 ID、日期、分类和参数需要在工具入口校验；停止后未开始的写入不再执行。

原生 DSH 的通用工具、审批和权限保持可解释。Agent 能力不限于写作，但默认个人助理设定与工具权限需要分别配置，不能因为换了角色文案就默认开放所有文件操作。

## 7. 角色、记忆和上下文

先核对固定基线已有的 persona、上下文、技能和记忆扩展能力，确定能直接复用的部分。不能仅因 DSH 有压缩与持久化就宣称它已覆盖全部个人长期记忆需求。

计划中的个人上下文插件负责可编辑的角色与风格、用户偏好、确认/候选记忆、修改和停用记录；DSH 继续负责上下文装配与历史压缩。使用其公开注入机制，并遵守模型可见内容可从日志追溯的要求。

稳定身份和必要偏好使用有预算的上下文；资料按需检索；技能按任务加载。记忆修改后验证下一轮生效，旧摘要不得重新恢复已撤销偏好。普通聊天不自动把所有经历写入长期记忆。

## 8. Linux 桌面适配

优先复用上游 Electron 主进程、隔离 preload、原生客户端与 Host 启动/退出协议。需要增加拾文的应用身份、独立数据路径、图标、Linux 构建目标及发行配置。

逐项检查并处理：原生 Node 依赖、平台 runtime 资源、托盘与关闭行为、文件选择、外部链接、应用菜单、单实例、Host 子进程退出、休眠唤醒和中文字体。

上游品牌更新服务和平台策略不能直接作为拾文的更新服务。当前计划使用手动安装升级；移除官方产品专用更新入口或替换为拾文的版本信息，不承诺尚未搭建的自动更新。遥测、官方账户及插件市场入口需逐项确认用途和默认行为，不能为通过启动而全局关闭安全检查。

Linux 原生桌面复用验证是最先执行的技术关卡。若发现必须更换桌面承载方式，先提交具体原因和替代方案评审；不得静默退回自建聊天或新 Electron Web 包装路线。

## 9. 实施步骤与完成条件

这些步骤是完整交付的顺序，不是缩减为只有页面的演示版。

1. **固定上游并跑通原生桌面。** 建立基线、可重复构建和独立数据目录；完成 Linux 启动、原生聊天、设置、退出及重启恢复。没有真实模型验证时单独标注，不能用假响应代替。
2. **替换视觉与导航。** 通过主题和界面插件完成聊天首页、侧栏、设置、弹窗、工具结果和错误状态的拾文风格；验证深浅主题、中文/英文、常用桌面分辨率及窄窗溢出。
3. **建立业务数据服务。** 实现记录、原件、日期、标签、草稿、版本和文章关联；验证事务、并发修改、重试幂等和重启恢复。
4. **接入原生对话。** 增加记录引用、保存动作及工具；验证对话保存日记、素材检索、创建文章与回顾查询，结果在业务页可见。
5. **完成业务页面。** 实现资料库、创作、发布前检查、回顾和相关设置；不引入第二套对话。
6. **接入个人上下文。** 验证角色、偏好、记忆候选、修改停用、注入预算与历史压缩衔接。
7. **完成迁移工具。** 对旧库只读扫描和预览，迁移到新库；核对数量、日期、来源、定稿文章和附件排除规则。旧会话无法无损转换为 DSH 日志时作为历史归档保留，不伪造为原生会话。
8. **桌面验收与打包。** Linux `.deb` 安装后完成实际运行、重启、关闭/托盘、升级保留数据、导出与故障恢复；补齐中英文文档、许可证和依赖声明。

## 10. 必须通过的验收场景

1. 应用只有一个会话列表和一套原生对话，重启后原会话可继续。
2. 用户说“把刚才的原话保存成昨天的日记”，准确保存原文、来源和明确日期，重复请求不会因同一次执行重试生成副本。
3. AI 整理日记与用户原话有明确区分；工具失败时界面和回复不能声称成功。
4. 从一份素材进入讨论，只有明确选取的引用被带入；讨论结果可创建文章项目。
5. 正在生成、等待审批、停止、网络断开、Host 意外退出都有可理解状态，不留下持续运行的后台任务。
6. 编辑器草稿和已保存正文在切换页面、关闭、重启后保持正确；冲突不能静默覆盖。
7. 导入历史内容与当天新增统计分开，7/14/30 天和自然月边界可复算。
8. 自定义代理商、语言与主题设置重启后生效；凭据不出现在 renderer 可读配置和日志里。
9. 在 Linux 常用桌面尺寸及窄窗检查导航、弹窗、输入区和滚动；未测试的桌面环境与托盘兼容性明确列出。
10. 插件停用时，其界面、工具和资源注册被释放；DSH 原生聊天仍能运行，资料文件保留。
