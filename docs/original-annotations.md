# 原文与 AI 标注

原文与 AI 标注使用不同文档 ID、正文、版本历史和附件归属。SQLite 分别保存记录及关联，文档不靠拼接正文或标题识别。普通 AI 文章仍是独立的普通文档，不自动成为标注。旧文档不自动拆分、不自动推断作者，也不重写历史写作活动。

## 来源与操作

`origin` 表示原文作者来源：personal、external、ai、translation、unknown；保存渠道和客户端身份另行记录。通过 MCP 传入的本人原文仍应显式声明 personal。普通编辑保留文档来源；来源纠正是单独的、带版本校验和请求 ID 的操作。

`annotationOf={recordId,versionId,contentHash}` 关联原文的不可变版本。contentHash 是该版本原始 Markdown UTF-8 字节的 SHA-256，不是当前原文的散列，也不是本地 revision。标注不能关联另一条标注；后续编辑不能重新指定关联。原文变化时旧标注保留，并显示基于较早版本。标注无论由谁补充编辑，都不计入个人正文和写作统计。

`originalVersionInfo` 获取锚点。`annotationCreate/List/Read/Update/Delete/Restore` 管理独立标注，List 的 deleted=true 仅列已删除项。更新使用标注自己的 revision。重复请求保留原 requestId 和完整参数，服务返回已提交结果；参数变更须使用新请求 ID。

父原文软删除后隐藏其标注，不修改标注自己的删除状态；父原文恢复后，独立删除的标注仍保持删除。不提供自动把标注合并进原文的操作。

## 同步、备份与导出

服务和 Android 同步使用 `1.0.0-draft.3`，先握手确认兼容性。旧协议不接受新结构写入，失败不会清除手机待同步队列。需要配套升级服务和手机；协议不兼容与节点离线是不同状态。

记录与版本快照携带标注关联。原文或指定版本尚未抵达时，标注操作保持依赖等待；不能降格成普通 AI 文档。版本锚点在完整复制、分支恢复和备份中保留。服务端备份 schema 15 保存关联表，恢复前验证关系及版本散列；Android 使用 Room 迁移新增元数据，不拆分历史正文。

同一天日记发生跨端合并时，源版本 UUID 和准确正文必须保留，合并结果另用新 UUID。经同步证实的日记 ID 映射才可归一化标注的原文 ID；源版本和散列不变。版本快照的 journalInput 保存源日记信息，恢复后仍可识别旧 ID 的待发操作。已经发送过的操作不得擅自修改请求字节。

完整备份包含原文、标注、关联、历史与附件。面向阅读的导出将原文、标注和附件分别放入 ZIP，以 JSON 索引记录关联；原文单独 Markdown 导出仍只导出原文。外部网络图片保持 URL，无法凭一个 URL 声称图片已离线保存。

## 回顾统计

回顾主卡片、每日趋势和个人原文明细统一使用个人原文字数；编辑活动作为独立辅助指标展示。`reviewPreview` 保留接口名称以兼容既有客户端，同时返回 `records` 和 `daily`，供三处展示使用相同的计算结果：

- **个人原文现存字数**：当前未删除、文档 origin=personal 的所有普通类型，按内容日期归入查询区间，计算整篇原文正文。未知内容日期不伪造日期。
- **观察到的个人编辑**：按真实 write 活动时间统计 personal 编辑的新增、删除、净增；用活动前后散列定位准确基线，同一个活动 ID 只计一次。导入、同步抵达、来源纠正、分类修改和恢复不会伪造成一次新写作。

沿用非空白 Unicode 字符口径，保留标点和 Markdown 标记，排除应用图片引用；不计标题、元数据和 AI 标注。库存描述当前保存内容，不是历史某一天的快照；两项数值不能相加。未明确归属的历史混合段落保持现状；统计依赖已保存的作者来源，不通过保存渠道推断作者。旧 `review` 的编辑流水及导入快照字段仅为兼容保留，主卡片不再读取这些字段作为个人原文字数。

## 验证边界

测试使用隔离的临时资料库和合成内容。覆盖接口权限、版本及幂等、标注图片、独立删除恢复、备份校验、完整复制、恢复分支、日记合并版本、字数口径和浏览器草稿重试。Android JVM 测试与仪器测试编译不等于真机同步、覆盖安装验收；发布记录须分别说明实际执行范围。
