# 移动端：Web 适配与离线客户端方案

> 2026-11-07 更新：Android 已进入完整功能联调验收，采用 React + Capacitor 界面与 Kotlin/Room 原生资料库。完整副本、双向同步、本机 AI、远端 DSH 和恢复流程均已有实现；具体通过与待验项目见 [当前验证记录](android/validation-2026-11-07.md)，不能仅凭入口或编译判定完成。架构依据见 [架构决策与生命周期](android/architecture.md)、[实施计划](android/README.md)、[同步协议](android/sync-protocol.md)和[界面与交互](android/ux-flows.md)。社区实现的参考边界见 [实现方式与取舍](android/community-implementation-reference.md)。

## 手机浏览器（当前源码 0.1.7）

沿用之前设计图的底部导航和独立阅读页面，在 760px 及以下宽度提供对话、素材、创作、回顾四个入口。对话使用 DSH 原生界面；素材和创作先显示标题、日期与搜索筛选，打开记录后以全宽阅读或编辑，返回列表可继续编辑未保存草稿。桌面保留窄列表、独立正文滚动和列表收起功能。

回顾提供今日、近 7/14/30 天与自然月；表格、代码块、来源长文本限制在正文区域内。中英文和明暗主题共用原有设置。侧边栏仍提供会话、Agent、插件和设置入口。

手机 Web 使用服务端资料库，服务电脑需要开机且网络可达。浏览器草稿恢复不是离线资料库同步。真实 Android/iOS 的软键盘、浏览器工具栏与安全区表现仍需真机验证。

## 独立移动客户端

Android 客户端在 `android/` 中实现完整本地资料库、离线记录、本机 AI 和连接服务后的同步。不配置电脑服务也能使用手机资料库、素材整理、创作与回顾；联网后可直接使用自己配置的模型。远端服务连接及自动/手动同步是可选能力。真实模型调用与后台执行可靠性须分别验收，不能用模拟成功替代。

手机独立资料库与远端库的离线副本分别保存。两者均保留完整正文、历史、关联、活动和库内附件/原件，不按近期缓存淘汰；前者不显示虚假的待同步，后者按已确认协议双向同步。同一库无论先在手机还是电脑创建，都可让另一端加入并保留原 libraryId/recordId，持续同步；不同库不自动合并。手机先建库接入服务不等于跨库复制。

## 多副本与服务角色

资料不依赖某一台电脑存活：各端持有完整本地副本，手机和电脑都可先创建库。服务是可替换的同步协调节点；协调服务丢失时，从完整存活副本恢复新服务，核对其他端版本分支并继续同步。当前不引入区块链、自动选主或任意两端后台直接互联，不能把数据多副本称为已经实现完全无中心的同步协议。

最终一致针对同一资料库：连接恢复、变更传输完成且冲突处理后，双方收敛到同一状态。一端停用不删除其他端资料；无法保证找回从未复制到存活节点的修改。首次复制未完成要显示不完整状态；一次服务接收成功不代表所有设备均已接收。同步不是历史备份，误删传播仍需回收站/版本恢复与独立备份。

## 数据与离线记录

手机持有本地资料库。在外面可以记录日记、想法、编辑本地完整资料；保存成功立即落到手机。界面区分“已保存到手机”“待同步”“已同步”“同步失败”和“有冲突”。手机创建的库与服务库的完整副本都长期保存。初次同步分批复制全库并显示真实进度；近期范围仅用于筛选和回顾，不是存储期限。

手机支持配置多个自行命名的服务节点，每个资料库分别配对、持有独立副本和同步队列；使用服务身份与授权凭据确认目标，IP 地址不作为资料库身份。回到局域网，应用打开且服务可达时按各库设置自动同步，也可手动同步当前库或全部可连接的库。后台同步的可用性需按移动平台验证，不承诺关屏后始终执行。

同步必须具备稳定记录 ID、修改版本、删除标记、增量游标、重试幂等和中断续传。双端同时修改时保留双方版本，由用户选择或合并；不能静默覆盖。切换主资料库不得自动合并两套数据。

服务端分别保存操作回执和资料变更日志。手机每轮先核对未确认上传的回执，再拉取变化和上传剩余修改；查不到回执表示结果未知，使用原操作编号重试。删除冲突通过原子的“恢复并更新”处理，离线正式保存保留逐日活动链；跨库复制本轮仅复制文本，并明确提示未复制的附件。远端 Agent 的连接断开与任务终止分别显示，重连先查询原任务，不自动重发。

初始化/恢复使用目标独占租约与原子 generation 校验；换机即使服务代次未变也执行授权对账，历史活动保留身份去重；暂缺附件进入可恢复等待；不完整恢复只保留救援暂存，不发布可写服务；合法长文通过分块载荷引用整体提交。服务端和原生实现均须通过对应故障场景，验收状态以验证记录为准。

## 独立 AI

- 有互联网、电脑不可达：手机直连自己的模型供应商，使用手机已有资料和移动端工具，讨论结果可立即保存到本地。
- 主服务可达：可选择服务端 Agent，检索完整资料库并调用电脑上的工具。
- 完全无网络：基础记录、编辑和本地检索仍可用；AI 需另行支持设备本地模型，不作为当前已具备能力。

移动端 Agent 的上下文、记忆、工具权限与任务状态需要独立维护。记录来源、作者、执行设备和 AI 整理行为分别保存。远端工具不可用时应明确提示，不虚构已搜索完整资料库。模型凭据使用设备安全存储，不随普通资料同步；对话是否同步由用户选择，资料关联需要可追溯。

## 实施顺序与验收

1. P0 验证本地 UI/原生持久化、成熟手机 Agent 方案与身份/恢复合同。
2. P1/P2 统一写入，完成正常全量/增量同步、附件通道、手机库首次启用和协调节点恢复；先用两个仿真副本验证。
3. P3/P4 建立 Android 完整本地库、备份基础、多节点和手动/自动同步，接入隔离独立服务。
4. P5 完成本机 AI 与远端 DSH，统一工具回执、权限、上下文和恢复规则。
5. P6/P7 做完整备份换机、较旧副本恢复/旧服务回归、多端汇合、真机生命周期和发布回归。Android 首发，iOS 工程另行规划。

同库身份、源设备、不可变变更与基线在本轮保留，存储和同步传输分层。未来对等同步可复用这些基础，但仍需改造并发判定、合并/删除收敛和设备连接，不作为轻量开关承诺。

首发平台为 Android，React + Capacitor 承担界面，Kotlin/Room 承担本地事务，WorkManager 调度后台同步。手机模型调用和本地资料工具在原生层执行，远端 DSH 保持服务端执行边界。工具链已锁定，未采用社区应用作为底座。端上本地大模型不在本轮目标内；iOS 工程另行规划。
